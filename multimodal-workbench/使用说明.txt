小小宇宙无敌 多模态渠道测试台

打开方式
双击外层的「中转站测试工具-多模态版.html」即可使用，无需安装依赖。
「文本模型」卡片内的「深度检测」提供通用检测、CCMax 验收与 Kimi KVV 专项。
CCMax 与 Kimi KVV 共用一个本地 Python 服务：双击外层「启动验收工作台.command」，打开 http://127.0.0.1:8877/。
CCMax 由独立的 Anthropic Messages 检测器执行；Kimi 的预检和全套验证由网页自动调用已集成的官方 KVV，无需另开 KVV 项目。

操作
1. 选择文本、图像、视频或音频。
2. 填入渠道地址、API Key、渠道实际使用的模型 ID。
3. 根据渠道文档选择协议。模型名可任意填写，也可获取渠道模型列表。
4. 输入提示词，必要时上传图片或待转写音频。
5. 可先查看请求预览，再点击开始测试。请求按渠道规则计费。
6. 返回媒体后可直接预览、打开或下载；导出报告可保存本次结果。

协议范围
文本：OpenAI Chat Completions、Responses、Anthropic Messages、Gemini GenerateContent。
图像：OpenAI 文生图、图片编辑、Gemini 图像生成/编辑。
视频：中转站 Videos（JSON，默认）、OpenAI 原生 Videos（multipart）、豆包/Seedance 原生任务、自定义 JSON 视频任务。
音频：OpenAI Speech、Chat Completions 音频对话、Gemini 原生 TTS、Transcriptions、Translations。
国内外模型只要渠道提供相应兼容协议即可接入，模型名称不限。
各模型支持的尺寸、时长、音色等取值不同，请以渠道文档为准。
未包含原生协议的供应商，可通过高级参数覆盖 JSON 请求字段、提交路径和视频查询路径；
若鉴权或工作流与已有协议不同，需要增加专用适配器，不能仅靠改模型名称。

视频任务
生成时自动查询进度；停止按钮取消本页等待，不会取消渠道上已提交的任务。
保留任务 ID 后，可点击「继续查询」获取结果，不需要重复提交生成请求。
查询路径用 {id} 作为任务 ID 占位符。OpenAI Videos 支持鉴权下载成品。
长时间任务达到等待上限后会保留任务 ID。

高级参数与批量
附加参数必须是 JSON 对象，顶层覆盖默认请求体；model 请使用模型名称字段，嵌套对象应填写完整。
同一协议可批量测试多个模型，顺序执行，每个模型提交一次，不会自动重试收费生成请求。
文本工作台侧重真实内容验收；原版文本深度检测提供流式、参数、并发等更多检查。

媒体与报告
图片、视频、音频都提供页面预览和打开/下载入口。
浏览器接收的二进制媒体会嵌入 HTML 报告；远程媒体 URL 仍受渠道有效期和权限限制。
JSON 响应下载保留详细字段（密钥会隐藏）；页面原始响应和 HTML 报告会缩略超长字段。
「体验预览」仅在本地生成演示图片、动画和提示音，所有结果明确标记为演示，无 API 费用。

连接说明
纯前端模式需要目标渠道允许浏览器跨域请求（CORS）。
网络错误也可能来自地址错误、TLS、浏览器混合内容限制或网络连接，不能仅凭 Failed to fetch 判断渠道故障。
某些媒体地址需要额外鉴权、跨域许可或不支持浏览器解码时，页面播放器可能无法加载。
API Key 只发送到配置的 API 地址，不保存在本地存储，也不会作为 Authorization 发送到第三方媒体站。
建议通过受信任的 HTTPS 渠道使用。基础多模态测试及浏览器直连的通用检测结果保留在当前页面，刷新或关闭前请及时导出。
CCMax / Kimi KVV 的本地验收报告另存于 integrations/reports/<任务ID>，不会因页面刷新而删除。本地服务仍在运行时，刷新可恢复当前任务或最近一次已结束任务的结果与下载入口；API Key 不随报告恢复。

开发与验证
源码位于 multimodal-workbench 目录。运行 python3 build.py 重新构建单文件。
运行 node --test engine.test.cjs 执行离线协议测试（不访问真实渠道）。
ui.test.cjs 使用本机 Playwright 和 Chrome，在浏览器中验证功能、报告及布局。

1.1 更新与适用范围
品牌改为「小小宇宙无敌」，文本深度检测位于文本模型旁边。
模型名称不限；协议预设有明确范围，不代表支持全球每一种私有接口。
模型名称提示只是推断，若渠道有自定义映射，可覆盖提示继续测试。
Seedream 通常是图像模型，Seedance 通常是视频模型，请勿混用。
视频出现 unmarshal / invalid character 错误时，可能是表单与 JSON 编码不匹配。
原生火山方舟任务路径返回 404 时，需要核对渠道是否提供该接口。
中转站视频 JSON 预设按 /v1/videos 提交，seconds 使用字符串，支持 metadata.url 成品地址。
该预设不直接上传文件；图生视频参考 URL 可按渠道文档在附加 JSON 的 images 或 metadata.content 中传入。
音频对话的本地录音支持 WAV / MP3；Gemini TTS 默认音色 Kore，PCM 自动封装 WAV。
不同音频协议需要不同模型和音色；未知错误需根据实际模型 ID 和返回体调整。
Realtime、嵌入、重排等接口未实现专项测试，不宣称完整覆盖。
当前结果记录 HTTP 状态、耗时、输出是否匹配、视频任务和媒体加载；
模型真实身份、计费准确性、生成质量、长期稳定性等不能靠一次成功请求证明。
1.1 版本的协议及界面验证使用本地模拟响应，当时未对用户渠道做真实生成实测。

1.2 模型选择修复
模型选择改为独立列表，不再使用浏览器原生 datalist。
选中模型后点下箭头可以再次查看全部模型；搜索框筛选列表但不修改已选模型。
× 可清空模型，也可直接输入渠道自定义模型 ID；上下键选择、Enter 确认、Escape 关闭。
获取列表最多等待 30 秒，支持取消、重新获取，失败时保留同一渠道的上次列表。
变更渠道地址、密钥或鉴权方式会作废旧列表和未完成的获取请求。
模型选择和手动输入会清空隐藏的批量模型，避免测试旧批量配置。

1.4 实时进度与媒体下载
- 测试期间显示当前阶段、已用时长、渠道真实百分比、排队位置、下次查询及查询次数。
- 优先使用渠道明确返回的剩余秒数；有足够进度变化时显示标注来源的趋势估算。
- 没有可用数据时显示暂时无法估计，不使用虚假百分比；等待/超时上限与完成时间分开。
- 支持常见顶层与 data/result/output/metadata 进度字段，未知私有格式需单独适配。
- 批量测试显示当前模型序号，每个模型独立计时；停止、继续查询不重复提交生成。
- 图片、视频、音频的下载按钮改为读取文件后触发浏览器下载，按返回 MIME 修正扩展名。
- CDN 请求不带渠道密钥；跨域读取受限、链接失效、空文件或错误页面会显示原因，不再静默跳转。
- 跨域读取限制属于媒体服务器设置，纯 HTML 无法强制绕过；可打开原媒体后另存为。
- 上游错误增加排查说明：结合 Request ID 查中转站/上游日志，不自动重试生成。
- 验证：79 项引擎测试、既有浏览器回归、新增 3 组进度测试、媒体真实下载事件及 CORS 失败测试通过。所有接口均为模拟，没有调用用户付费渠道。

1.7 CCMax 验收与 Kimi KVV
入口：文本模型 → 深度检测 → CCMax 验收 / Kimi · KVV。
启动：双击「启动验收工作台.command」。本地服务只监听 127.0.0.1:8877；可关闭终端停止服务。
已有 KVV Python 环境会自动复用。其他电脑首次使用需要 Git、Python 3.9+ 和 uv；启动脚本会获取固定版本官方源码、校验必要素材，并建立独立 Python 3.13 环境安装依赖。详见 README.md。

CCMax
- 参考 api-channel-acceptance-test 附件的方法，适用 Anthropic /v1/messages 兼容渠道。
- 8 类：伪造 thinking 签名、message_start 唯一性、message_stop 收尾、连接关闭、流中 error、错误格式、usage/cache 结构、工具 JSON 增量。
- 快速默认 1 次签名 + 3 次 SSE + 1 次强制工具 + 1 次非法模型，共 6 次请求。批量默认 5 + 50 + 2，共 57 次；可自定义次数。
- 支持 x-api-key / Bearer。最多 2 路并发；单次超时可调，message_stop 后独立 5 秒关闭宽限。
- 401/429/超时不视为签名放行；SSE error 表示本次调用失败，不单凭它判断中转违规。
- 保存原始请求、响应、响应头（含重复 request ID）、SSE 与 message ID。报告不保存 API Key。

KVV
- 使用 https://github.com/MoonshotAI/Kimi-Vendor-Verifier ，集成版本 66092cf。
- 「11 项预检」沿用本地预检清单：两种 thinking 基础请求、两种非法温度、流式/非流式 schema、dynamic tools、JSON object、required tool choice、两项 prompt tokens。
- 「全套验证」运行官方 tests/params、tests/tool_call_json_schema、tests/k3_features、tests/prompt_tokens。当前版本收集 611 个 pytest 项，包括官方跳过项与本地边界检查；项目数不等于实际 API 请求数。
- 不包含独立 OCRBench、MMMU、AIME、BEAM、DeepSWE benchmark，不等于官方认证或模型身份鉴定。
- K3 特性和 token 常量基于 K3 契约，其他型号可能不适用。thinking 格式可选 Kimi / 开源部署 / 不发送。
- 保留官方原始用例；本地适配器增加进度、取消与结果保护：参数拒绝遇到网络/鉴权错误或无关 400，记失败/无法判定，不能误记为参数校验通过。
- 本地执行禁用 SDK 自动重试与 pytest 失败重跑；脚本内部可能有多次请求。已通过测试数按真实用例结果统计，跳过项单列。

运行与报告
- 网页显示实际完成数量、已用时间和基于已完成用例的粗略剩余时间。不同用例耗时差异很大，估计不是完成承诺。
- 取消会关闭本地请求 / 测试进程；已经到达渠道的请求可能仍按渠道计费。
- 刷新本地页面可重新连接当前正在运行的验收任务。
- 完成或取消后可下载 HTML 报告、JSON 结果、ZIP 证据；本机副本存于 integrations/reports/<任务ID>。
- 所有密钥仅在会话与任务内存使用，不写入配置。测试模型响应中的正文会随脱敏报告保存。
- 1.7 版本集成阶段使用模拟接口与本机假服务验证，当时未自动调用你的付费渠道。


1.8 通用检测统一与专项验收加强
- 通用检测统一为与 CCMax / Kimi KVV 相同的灰绿界面：左侧渠道配置与检测范围，右侧检测维度、日志和报告。支持手机单栏，嵌入页面自动调整高度，避免开始按钮被内层滚动区域遮住。
- CCMax 增加最终 message_delta、stop_reason 与最终 usage 核查，并检查独立请求是否复用了 message ID。异常会保留到逐样本证据与汇总结果中。
- CCMax 增加正向 SSE 基线保护：先确认有效请求能正常开始、完整结束且没有流中错误。若有效请求基线未通过，不能仅凭拒绝伪造签名或非法模型就判定相关检查通过，而会标记为无法判定。
- KVV 显示实际发出的 API 请求数，并将请求与官方用例关联；用例数量与请求数量分开呈现。保存脱敏后的传输证据，便于核对返回状态、请求标识和流式异常。
- KVV 因网络或传输错误无法完成的用例单列为「无法判定」，保留原始 pytest 结果用于排查，不能将这类错误直接解释成模型能力不合格或渠道造假。参数 / Schema 的 Thinking 格式设置不改写官方 K3 特性及 Token 用例的原生请求。
- 专项验收可直接获取渠道模型列表、反复切换或手动填写未列出的映射模型 ID。切换渠道配置后作废旧列表；获取失败不清空已填写的模型。
- 报告增加明确的验收结论、实际请求计数和传输异常证据。本地服务会话内，刷新可恢复正在运行或最近一次已结束的验收任务，不会重新提交测试；脱敏报告仍保存在 integrations/reports/<任务ID>。
- 具体失败项、无法判定项与证据以 integrations/reports 中对应任务的报告为准；验收结论不等同于模型身份鉴定。
- 本轮同时完成离线界面回归，覆盖模型获取与切换、失败恢复、旧请求返回保护、报告恢复，以及桌面和手机布局。

1.10 专项名称与服务状态说明
- 标题统一为「CCMax渠道验收」，页签为「CCMax 验收」。CCMax 使用独立的 Anthropic Messages 检测器，不运行 KVV。
- 服务状态随当前专项切换：CCMax 显示本地验收服务的连接状态；Kimi 才显示集成的 KVV 版本。正在连接、连接失败和直接打开 HTML 时均显示相应状态，不将服务连通等同于 KVV 已成功启动或测试通过。
- Kimi 的「11 项预检」和「全套验证」由同一个本地服务自动调用已集成的 MoonshotAI 官方 KVV，无需另行打开或启动 KVV 项目。用例启动结果与执行情况以任务日志、进度和报告为准。
- 切换专项、首次异步连接、恢复历史报告以及连接暂时中断后恢复时，服务标识保持与当前专项一致。
- HTML 下载报告新增范围与配置、问题与影响、逐项预期/实际对照、请求耗时和证据明细；请求样本数与检查项数分开统计。
- 每项展示怎么测、预期行为、真实观测、结果解释和排查建议，可按状态筛选、搜索并跳转到对应样本；上游 Request ID、HTTP、请求/响应和 SSE 可展开查看。
- HTML 报告自带样式，无外部资源依赖，适配手机；支持打印/保存 PDF。打印会展开证据；超长原始字段在页面中明确标注缩略，原始采集数据保留于 JSON / ZIP。
- 旧任务重新下载即使用新版模板，不重新调用渠道；已有本机报告可以继续保留。
